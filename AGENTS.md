# AGENTS.md

Guidance for AI coding agents working in the IceProd repository.

## Overview

IceProd is the IceCube grid production system. It is a set of services backed by MongoDB.

| Component | Path | Notes |
|---|---|---|
| REST API | `iceprod/rest/` | Tornado + `rest_tools`. Handlers live in `rest/handlers/*.py`. Each handler module's `setup()` returns its routes, database, and Mongo indexes. |
| Website | `iceprod/website/` | Tornado server-rendered pages. Handlers are in `website/handlers/`, Tornado templates in `website/data/www_templates/`, and static assets in `website/data/www/`. It talks to the REST API through `RestClient`; it never accesses Mongo directly. |
| Credentials service | `iceprod/credentials/` | Token storage and refresh. |
| Services / actions | `iceprod/services/` | Background actions such as submit, materialization, and status changes. |
| Grid / server | `iceprod/server/` | HTCondor plugin (`plugins/condor.py`), queueing, and state machines (`states.py`). |
| Scheduled tasks | `iceprod/scheduled_tasks/` | Run-once scripts deployed as k8s CronJobs. `dataset_monitor.py` exports the Prometheus metrics. |
| Core | `iceprod/core/` | Dataset config, schema, and resources (`resources.py` holds the default task requirements). |
| Admin scripts | `resources/` | One-off maintenance scripts and the Grafana dashboard JSON (`resources/grafana/`). |
| Docs | `docs/` | Sphinx. The REST API docs are generated by `automodule` from handler docstrings. |

## Key Concepts

- **Status state machines** live in `iceprod/server/states.py` (`DATASET_STATUS`, `JOB_STATUS`, `TASK_STATUS`). Always use these constants instead of hard-coding status lists.
- **Auth**:
  - REST handlers use `@authorization(roles=[...])` for the role check, and `@attr_auth(arg='dataset_id', role='read'|'write')` for per-dataset access.
  - When one request covers many datasets, use the batch helpers on `AttrAuthMixin` (`iceprod/rest/auth.py`) instead of calling `manual_attr_auth` in a loop. These are `self.filter_attr_auth(arg, vals, role)`, which returns the allowed subset using batched `$in` queries, and `self.get_readable_dataset_ids()`, which parses the `dataset_ids` query argument and returns 403 if any is unreadable.
  - The access rule itself lives only in `AttrAuthMixin._attr_auth_allowed`.
  - The `user` role and the `users` group are defined by the same IceCube token claim, so every user token is in `users`. New datasets are readable by `users` unless `auth_groups_read` is set.
  - The `admin` and `system` roles bypass attribute auth.
- **Separate databases**: datasets, jobs, and tasks are in *different* Mongo databases, so `$lookup` across them is not possible. Aggregate per collection and join in Python.
- **Task requirements** may be missing from a task document. Fall back to `Resources.defaults`.
- **Prometheus**: `dataset_monitor` is a short-lived CronJob that is scraped while it runs. Metrics carry `dataset`, `username`, and `group` labels. Dashboards must tolerate gaps between runs (`last_over_time`) and dedupe across pod labels.

## Development

### Environment

- Python 3.12–3.14. The local virtualenv is `env/` (use `env/bin/python`; there is no bare `python` on PATH).
- Install with `pip install -e .[tests]`.
- `pyproject.toml` sections marked "do not edit — autogenerated" are managed by CI. Do not edit them.

### Tests

- The tests need a MongoDB replica set on `localhost:27017` (see `resources/run_mongo.sh`). Override it with `DB_URL`.
- Run all tests with `env/bin/python -m pytest tests`.
- Run a subset with `env/bin/python -m pytest tests/rest/tasks_test.py -k counts`.
- The pytest `asyncio_mode` is `auto`, so write async tests as plain `async def test_...`.
- Fixtures:
  - `tests/rest/conftest.py` provides `server`. It returns `server(roles=[...], groups=[...], username=...)`, a real REST client backed by Mongo.
  - `tests/website/conftest.py` provides `server`. Its `client.req_mock.add_mock(path, ret_or_callable)` mocks REST calls by exact path; a callable receives `(method, path, args)`. HTTP errors are raised as `httpx.HTTPStatusError`.
- `tests/server/daemon_test.py::test_01_Daemon` is known to fail in some sandboxed environments (pre-existing).

### Lint and type checks

- CI linting uses **ruff** (config in `pyproject.toml`; `E501` and many other rules are ignored): run `env/bin/ruff check iceprod`. Do not reformat code to satisfy flake8's defaults.
- Type checking uses **ty** (config in `[tool.ty]` in `pyproject.toml`). Run `env/bin/ty check --python env`; the `--python env` flag is required, otherwise ty can't find the dependencies and reports many false unresolved imports. Do not use mypy.
  - The baseline has about 21 pre-existing diagnostics. Compare the counts before and after your change, and do not add new ones.
  - Mixins that use attributes from `PublicHandler`/`APIBase` should declare them with class-level annotations instead of `# type: ignore`.
  - Use `# ty: ignore[...]` for deliberate suppressions.

## Conventions

- **Line endings**: many templates (`website/data/www_templates/*.html`) and some test files (`tests/rest/tasks_test.py`, `tests/rest/jobs_test.py`, `tests/scheduled_tasks/*`) use **CRLF**. Preserve CRLF when editing them, because Python read/write round-trips silently convert to LF. Check a file with `grep -c $'\r' <file>`.
- **New REST endpoints**: register the route in the module's `setup()`, write a docstring with Args/Params/Returns (it becomes the API docs), and add tests covering roles and attribute auth.
- **New website pages**: subclass `PublicHandler` and use `@authenticated`. The nav highlight comes from the first URL path segment (the `section` template variable). New config goes in `website/config.py` as environment variables, through `from_environment_as_dataclass`.
- **REST multi-dataset requests** take `|`-separated ids in GET query strings, with a maximum of 100 (`MAX_DATASET_IDS`). Callers must chunk.
- `CHANGELOG.md` is generated by the release workflow. Do not edit it by hand.

## Git

- Work on the current branch. Do not create branches or push.
- Commits made with AI assistance must include a `Co-Authored-By:` trailer naming the model.
- `PLAN.md` and `HANDOFF.md` are gitignored scratch files for agent planning and progress. Do not reference them from other files.
